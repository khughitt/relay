# relay v0.1.0 publication Implementation Plan

Status: draft for review, 2026-10-18. Task: `relay-c19c0a`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public, immutable `v0.1.0` tag of relay that a consumer installs as `git+https://github.com/khughitt/relay.git#v0.1.0` with no credentials and no local checkout, with every packaged path working, and a release record saying what it verifies.

**Architecture:** Three repository changes, then two publication steps. (1) Fix the one packaging defect found while preparing this plan: a git-installed relay lacks `jsonc-parser`, so `relay install` fails. (2) Add a portability check that installs relay from a git spec in a credential-free scratch environment, and rehearse it against a scratch bare clone before anything goes public. (3) Write the release record and correct the docs' Darwin claims. (4) Push, tag, prove the check cannot reach a private repository, and make the repository public. (5) Run the check against the public tag and record the result.

**Tech Stack:** Node >=22 ES modules, `node:test`, npm 11, git, gh, gitleaks.

**Spec:** ops `docs/specs/2026-09-16-relay-design.md`, approved after `d7e2c33`. This plan implements §8 "Cutover and recovery" (its first two paragraphs: a public GitHub remote, the pinned `git+https` form, immutable tags, and verifying installation from a clean clone and cache with no local relay checkout or GitHub credentials) and the release-verification bullet on installing the remote tag. The task record `relay-c19c0a` carries the procedure details and the 2026-10-18 rescope and pre-plan findings notes.

## Decisions this plan makes

- **jsonc-parser becomes a regular dependency.** `package.json` names it in `bundledDependencies`. A git install packs the cloned tree, which has no `node_modules`, so the package arrives without it. Because the name is marked bundled, npm does not fetch it either. A rehearsal with `git+file` of a bare clone at a scratch tag and an empty cache showed this: `relay list` and the exports work, and `relay install` fails with `install_failed: ERR_MODULE_NOT_FOUND: Cannot find package 'jsonc-parser'`. The local tarball smoke test passes only because `npm pack` runs beside a populated `node_modules`. Removing `bundledDependencies` fixed the same rehearsal: npm fetched `jsonc-parser@3.3.1` from the registry with an integrity hash, `relay install` produced its plan, and `npm ci` reproduced the install. familiar already depends on `jsonc-parser` 3.3.1, so its tree gains nothing. Two alternatives were rejected. Vendoring a copy under `src/` keeps offline installs, but it adds a hand-maintained third-party tree and a second license to track. A `prepare` script installs dev dependencies (TypeScript) on every consumer install, and `--ignore-scripts` skips it.
- **Darwin does not gate publication** (task note 2026-10-18). The spec requires a Darwin live probe before changing Darwin's installed hooks. That run is `relay-848c0f`, and it gates the Mac cutover.
- **The tag goes on main after the merge,** never on the branch. A failed check after the tag is fixed forward as `v0.1.1`. The tag is never moved or deleted.

## Global Constraints

- Runtime: Node >=22, ES modules, Node built-ins only; no new dependency. `jsonc-parser` stays the one runtime dependency.
- Tests: `just test-one <args>` while working, `just test-fast` before every commit, `just gate` before integration. Never call `node --test` or `npm test` directly.
- Node 22 floor runs: `NODE22_BIN=$(dirname "$(ls -d ~/.nvm/versions/node/v22.*/bin/node | sort -V | tail -1)")`, then `PATH="$NODE22_BIN:$PATH" just gate` (or `"$NODE22_BIN/node" <script>`). The first command must print `v22.x` from `PATH="$NODE22_BIN:$PATH" node --version`.
- The consumer pin form, exactly: `git+https://github.com/khughitt/relay.git#v0.1.0`.
- Tag: annotated, name `v0.1.0`, message `relay v0.1.0`. No other tag is ever created in the relay repository. Rehearsal tags exist only inside scratch bare clones under the system temp directory.
- gh: every command is `GH_TOKEN=$(gh auth token --user khughitt) gh …`. `gh api user --jq .login` must print `khughitt`. `<work-account>` must never be used. Never run `gh auth switch`.
- External actions (pushing main, pushing the tag, changing visibility) happen only in Task 4, and only after the user authorizes Task 4 explicitly. Approving this plan does not authorize them.
- Conventional commits, no AI attribution. Committed docs use repository-relative paths, `~`, or `$HOME`; no machine-specific absolute paths.
- The package stays `"private": true`. This is not an npm registry publication.

## Review Focus

1. **Host credentials leaking into the portability check.** An SSH agent, a git credential helper, `GH_TOKEN`, or `~/.npmrc` could let the check reach a private repository and pass for the wrong reason. Expected: the check reaches GitHub only anonymously. Pinned by Task 4 Step 6: run against the pushed tag while the repository is still private, and it must fail at `install`.
2. **The consumer lockfile records `git+ssh://git@github.com/khughitt/relay.git#<sha>` for a `git+https` GitHub spec,** as familiar's `familiar-theme` entry does. `npm ci` from that lockfile, with no SSH key, must still install. Pinned by the `ci` check in Task 2, which runs in the credential-free environment against the public tag in Task 5.
3. **A tag on the wrong commit.** A lightweight tag, a tag on the branch, or main moving between the gate and the tag. Expected: one commit everywhere. Pinned by Task 4 Step 5, which compares main `HEAD`, `v0.1.0^{commit}` and the remote's peeled tag, and by Task 2's `lockfile` check, which compares the lockfile's resolved commit with `--commit`.
4. **A shipped path that needs a package the consumer does not get** (the jsonc-parser class). Pinned by Task 1's tracked-files pack test and the smoke's `relay install` plan check.
5. **A Node 22 consumer.** Expected: install and smoke behave the same on the floor runtime. Pinned by running the check under Node 22 in Task 2 Step 6 and Task 5 Step 2.

## Out of scope

- The Darwin probe's bundle builder, D1 and D2 assume a bundled `jsonc-parser`: D1 installs offline, and D2 copies the dependency from `node_modules/relay/node_modules/jsonc-parser`. Task 1 breaks that assumption. `relay-848c0f` updates those three before it builds its bundle, because the probe is unshipped Mac tooling that is next used there.
- `relay-480b51`'s shipped-doc inaccuracies do not gate the tag. A later patch release carries them if they have not landed first.

### Task 2: Portability check, rehearsed before publication

**Files:**
- Create: `tools/release/portability.mjs`
- Modify: `tools/README.md`: one line after the vendored table saying that `tools/release/` belongs to this project.

**Interfaces:**
- Consumes: `test/fixtures/consumer-smoke.mjs` (Task 1), read from the checkout the script lives in.
- Produces: `node tools/release/portability.mjs --spec <npm git spec> --commit <40-hex sha>`. Exit 0 when every check passes, 1 when one fails, 2 on a usage error. Output is one line per check, `ok <check>: <detail>` or `FAIL <check>: <detail>`, and then `portability: pass` or `portability: fail`. Checks run in order and stop at the first failure.

- [ ] **Step 1: Implement the scratch environment.** All work happens in `mkdtemp(join(tmpdir(), 'relay-portability-'))`, which is removed on exit, SIGINT and SIGTERM. Child processes get an environment built from nothing but these keys:
  - `PATH` = `dirname(process.execPath) + ':/usr/bin:/bin'`
  - `HOME` = `<tmp>/home` (created empty)
  - `npm_config_cache` = `<tmp>/cache`
  - `npm_config_userconfig` = `<tmp>/npmrc` (an empty file)
  - `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0`
  - `GIT_SSH_COMMAND` = `ssh -o BatchMode=yes`
  - `RELAY_STATE_DIR` and `XDG_CONFIG_HOME` under `<tmp>`

  No variable from the parent passes through: no `SSH_AUTH_SOCK`, `GH_TOKEN` or `npm_config_*`. The consumer is `<tmp>/consumer` with `{"private":true,"type":"module"}`.

- [ ] **Step 2: Implement the checks**, each one a child process with a 180 s timeout:
  1. `install`: `npm install --no-audit --no-fund <spec>` exits 0.
  2. `lockfile`: `packages["node_modules/relay"].resolved` ends with `#<commit>`, and `packages["node_modules/jsonc-parser"]` has a `resolved` under `https://registry.npmjs.org/` and an `integrity`. The detail line prints both `resolved` values.
  3. `smoke`: `consumer-smoke.mjs` copied into the consumer prints `installed package verified`.
  4. `ci`: after removing `node_modules`, `npm ci --no-audit --no-fund` exits 0 and the smoke passes again.

- [ ] **Step 3: Build the rehearsal remote.** Create a scratch directory under the system temp directory, never inside the repository. Run `git clone --bare <main checkout> <scratch>/relay.git`, which carries `main` and `release/v0.1.0` because worktrees share refs. Then tag inside the scratch clone only: `git -C <scratch>/relay.git tag -a v0.1.0-pre -m pre main` and `git -C <scratch>/relay.git tag -a v0.1.0-fix -m fix release/v0.1.0`.

- [ ] **Step 4: Watch the check catch the defect**

Run: `node tools/release/portability.mjs --spec git+file://<scratch>/relay.git#v0.1.0-pre --commit $(git rev-parse main)`
Expected: `ok install`, then `FAIL lockfile: …jsonc-parser…` (the lockfile has no `jsonc-parser` entry), `portability: fail`, exit 1.

- [ ] **Step 5: Watch the fixed branch pass**

Run: `node tools/release/portability.mjs --spec git+file://<scratch>/relay.git#v0.1.0-fix --commit $(git rev-parse release/v0.1.0)`
Expected: four `ok` lines, `portability: pass`, exit 0.

- [ ] **Step 6: Repeat Step 5 on the Node 22 floor** with `"$NODE22_BIN/node" tools/release/portability.mjs …`. Expected: `portability: pass`. Then remove the scratch directory.

- [ ] **Step 7: Fast check and commit**

Run: `just test-fast` (all pass), then:

```bash
git add tools/release/portability.mjs tools/README.md
git commit -m "feat(tools): release portability check for a git-installed relay"
```
