## Decisions this plan makes

- **jsonc-parser becomes a regular dependency.**
  - The defect: `package.json` lists it in `bundledDependencies`. A git install packs the cloned tree, which has no `node_modules`, so the package arrives without it. Because the name is marked bundled, npm does not fetch it either.
  - The evidence: a rehearsal with `git+file` of a bare clone at a scratch tag and an empty cache. `relay list` and the exports work, but `relay install` fails with `install_failed: ERR_MODULE_NOT_FOUND: Cannot find package 'jsonc-parser'`. The local tarball smoke test passes only because `npm pack` runs beside a populated `node_modules`.
  - With the name removed from `bundledDependencies`, npm fetched `jsonc-parser@3.3.1` from the registry with an integrity hash, `relay install` produced its plan, and `npm ci` reproduced the install. familiar already pins `jsonc-parser` 3.3.1 exactly, so its tree gains nothing.
  - Rejected: vendoring a copy under `src/`, which keeps offline installs but adds a hand-maintained third-party tree and a second license to track. Rejected: a `prepare` script, which installs dev dependencies (TypeScript) on every consumer install and is skipped under `--ignore-scripts`.
- **Darwin does not gate publication** (task note 2026-10-18). The spec requires a Darwin live probe before changing Darwin's installed hooks. That run is `relay-848c0f`, and it gates the Mac cutover. Task 2 keeps the probe runnable at `v0.1.0`, so the Mac can verify the tag consumers pin rather than a later commit.
- **GitHub holds only reviewed history before it goes public.**
  - Two exposures exist today. The work gh account's login has been in a task record since `188b541`, which puts it in about 1010 commits' trees. The 2026-10-17 force-push (`d7ac402` → `07ee5ef`) left its pre-images on GitHub, fetchable by sha, and its activity event names the old head.
  - Publication would make both permanent. The public tasks and familiar repositories carry neither.
  - `relay-06b733`, a separate task, rewrites the login out of every ref and recreates the private repository, which purges the pre-images. It must finish before Task 5.
  - Rejected: publishing as is. A rewrite after publication cannot recall what was published.
- **One release commit.** Task 5 fixes `REL` after the gates. Every later step gates, scans, pushes, tags and compares against `REL`, never against a moving `main`. A failed check after the tag is fixed forward as `v0.1.1`. The tag is never moved or deleted.

## Review Focus

1. **Host credentials leaking into the portability check.** An SSH key or agent could let the check reach a private repository and pass for the wrong reason. OpenSSH finds keys through the passwd home directory, whatever `$HOME` says. So could a git credential helper, `GH_TOKEN` or `~/.npmrc`. Expected: the check reaches GitHub only anonymously. Pinned twice, by the private-remote refusal: in Task 3 Step 7 before anything is pushed, and in Task 6 Step 5 against the pushed tag. The `reach` check's verbatim git error tells an auth refusal from a network failure.
2. **The consumer lockfile records `git+ssh://git@github.com/khughitt/relay.git#<sha>` for a `git+https` GitHub spec**, as familiar's `familiar-theme` entry does. `npm ci` from that lockfile, with SSH disabled and an empty cache, must still install. Pinned by the `ci` check, which runs against the public tag in Task 7. Pre-checked 2026-10-18 in this environment against the public `git+https://github.com/khughitt/familiar-theme.git#v0.3.0`: npm fetched it over https from `codeload.github.com`.
3. **A tag on the wrong commit.** Main moves between the gate and the tag, the tag is lightweight, or the tag lands on the branch. Expected: one commit everywhere. Pinned by `REL` in Task 5, and by Task 6 Step 4, which compares `REL`, `v0.1.0^{commit}`, the remote's peeled tag and the remote's main. The `lockfile` check compares the lockfile's resolved commit with `--commit`.
4. **A shipped path that needs a package the consumer does not get** (the jsonc-parser class). Pinned by Task 1's tracked-files pack test, its pack-list equality, and the smoke's `relay install` plan check.
5. **A Node 22 consumer.** Expected: install and smoke behave the same on the floor runtime. Pinned by running the check under Node 22 in Task 3 Step 6 and Task 7 Step 2.
